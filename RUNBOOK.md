# AquaFresh Log Monitoring — Incident Response Runbook

## Purpose

This runbook describes how staff should investigate, contain, and report alerts generated by the AquaFresh Log Monitoring system.

## General Response Procedure

1. Review the alert timestamp, rule name, severity, IP address, and description.
2. Compare the alert with the relevant authentication or web access logs.
3. Record findings and preserve relevant logs as evidence.
4. Apply containment measures when suspicious activity is confirmed.
5. Notify the responsible manager and document the actions taken.
6. Verify whether the activity continues after containment.

## Alert Type 1: Failed SSH Login

**Severity:** High

### Investigation

1. Record the source IP address, username, and timestamp from the alert.
2. Check `auth.log` for additional failed attempts or unexpected successful logins from the same IP.
3. Determine whether the username and source IP are associated with an authorized user.
4. Preserve relevant log entries for investigation.

### Containment

1. If repeated or unauthorized attempts are confirmed, notify the system administrator.
2. Ask the authorized administrator to block the suspicious IP using the server firewall, following organizational approval procedures.
3. If an account may be compromised, ask the administrator to secure the account, rotate its credentials, and review active sessions.
4. Verify that suspicious attempts have stopped.

### Reporting

1. Record the IP address, targeted username, timestamps, evidence, and actions taken.
2. Notify the responsible manager of the high-severity alert.
3. Document the final outcome and any recommended preventive measures.

## Alert Type 2: HTTP POST Request

**Severity:** Medium

### Investigation

1. Record the source IP address and timestamp.
2. Check `access.log` for the corresponding request path, HTTP status code, and nearby requests.
3. Determine whether the POST request relates to a normal application action, such as login, or potentially suspicious activity.
4. Review related authentication alerts and other log entries from the same IP.

### Containment

1. If malicious activity is confirmed, notify the system administrator.
2. Request an approved firewall block or other suitable restriction for the source IP when justified by the evidence.
3. If the request indicates possible account abuse, secure the affected account and review related activity.
4. Verify that the suspicious activity has stopped and legitimate application access remains available.

### Reporting

1. Record the source IP, timestamp, request details, investigation findings, and containment actions.
2. Notify the responsible manager if suspicious or malicious activity is identified.
3. Document whether the request was legitimate, suspicious, or confirmed malicious.

## Important Notes

* An alert is an investigation trigger, not proof of an attack.
* Do not block an IP or disable an account solely because an alert exists; assess the evidence and follow approval procedures.
* Preserve relevant logs and avoid modifying evidence.
* Record the incident outcome and escalate unresolved or recurring activity to the responsible administrator.
